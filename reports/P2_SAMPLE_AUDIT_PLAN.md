## 5. Six Review Dimensions (Per CAQS §1.6)

Each sampled item receives independent verification across six dimensions:

### 5.1 Dimension A: Key Correctness
- **Method:** Independent hand-solve against stem + choices + exhibits (if any)
- **Evidence:** Documented calculation/reasoning trace; compare to stored `CorrectChoice`
- **Pass:** Independent result matches stored key exactly
- **Fail:** Mismatch → escalate per §7

### 5.2 Dimension B: Explanation Correctness
- **Method:** Verify `ExplanationCorrect` matches independent solution
- **Checks:**
  - Accounting principle named (ASC, COSO, IAS, IMA standard)
  - Formula with substituted values shown
  - Arithmetic result matches `CorrectChoice`
  - Business interpretation present
  - No uncertain language ("I think", "probably")
- **Pass:** All checks satisfied
- **Fail:** Any check fails → escalate

### 5.3 Dimension C: Stem Clarity
- **Method:** Read stem cold; assess ambiguity, missing assumptions, contradictory data
- **Checks:**
  - Single defensible interpretation
  - All required data present in stem/exhibits
  - No textbook phrasing — business realism (CAQS §3.2)
  - Named stakeholder, company, trigger, task (if case-linked)
- **Pass:** Clear, unambiguous, realistic
- **Fail:** Ambiguity or missing data → escalate

### 5.4 Dimension D: Distractor Plausibility
- **Method:** Evaluate each non-correct choice
- **Checks:**
  - Each distractor maps to documented misconception/exam trap
  - No "obviously wrong" throwaway distractors
  - Distractors are distinct (no logical equivalence per CAQS §6.3)
  - `ExplanationWrong[X]` is choice-specific, non-empty, explains the error
  - `ExplanationWrong[CorrectChoice]` is empty (Rule 2 / DL-008)
- **Pass:** All 3 distractors plausible, distinct, explained
- **Fail:** Any distractor fails → escalate

### 5.5 Dimension E: Domain/Topic Alignment
- **Method:** Cross-reference `Topic`, `BlueprintDomain`, `LOSTag` against IMA CSO
- **Checks:**
  - Topic matches actual question content
  - BlueprintDomain aligns with IMA Part 2 CSO section
  - No Part 1 concepts in P2 items (Part2OnlyFlag = true per Rule 13)
  - FormulaReference / DecisionTreeReference resolve to valid entries
- **Pass:** All metadata accurate and aligned
- **Fail:** Misalignment → escalate

### 5.6 Dimension F: Lifecycle / Certification Provenance
- **Method:** Verify metadata fields
- **Checks:**
  - `question_state: "Certified"` (not Unprocessed/In Audit/Editorial Queue/Archived)
  - `certification_batch` + `certification_date` present (Rule 16)
  - `Part2OnlyFlag: true` (Rule 13)
  - `CognitiveLevel` valid per TAXONOMY_REGISTRY.md (Rule 11)
  - No `question_state` changes without REVISION_HISTORY.md entry (Rule 1)
- **Pass:** All provenance fields valid
- **Fail:** Missing/invalid provenance → escalate

## 6. Reviewer Decision Categories

| Decision | Criteria | Action |
|----------|----------|--------|
| **PASS** | All 6 dimensions PASS | Item confirmed certified |
| **CONDITIONAL PASS** | 1-2 dimensions have minor issues (metadata only, no correctness impact) | Document issue; item remains certified; track for remediation |
| **FAIL — CORRECTNESS** | Dimension A or B FAIL | **Immediate escalation** — quarantine item (Certified → In Audit), file DL defect, remediate before any delivery |
| **FAIL — PROVENANCE** | Dimension F FAIL (missing certification stamps, invalid state) | Quarantine until provenance restored |
| **FAIL — STRUCTURAL** | Dimension D (DL-008/DL-026) or E (Rule 13/14) FAIL | Quarantine; structural remediation required |

## 7. Escalation Rules

| Trigger | Escalation Path |
|---------|-----------------|
| Any **Correctness FAIL** (Dim A/B) | 1. Immediate `question_state: "In Audit"` via `stamp_cert.js` --audit<br>2. File DL defect in `DEFECT_LIBRARY.md`<br>3. Notify Accountant + Release Manager<br>4. Remediation per CAQS §9.4 workflow |
| **≥3 items FAIL** in same pack/domain | Pack-level review — suspend pack from delivery pool pending root cause |
| **Provenance FAIL** (Dim F) | Restore provenance stamps from backup or re-certify per CAQS §1.6 |
| **Reviewer Uncertainty** (confidence < 90) | Second independent reviewer required; both must agree |

| Defect Class | Handling |
|--------------|----------|
