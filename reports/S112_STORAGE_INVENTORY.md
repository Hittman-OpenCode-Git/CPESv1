## 2. Orphan & Duplicate Analysis

### 2.1 No Orphaned Keys

All 18 storage keys are actively read and written by at least one module. No write-only keys exist. No keys are set from test scripts without corresponding reads in production code.

### 2.2 No Duplicate Repositories of Truth

Each data domain is stored in exactly one location:
- **Session state:** `cmaP1SessionState` (with checkpoint fallback)
- **History:** `cmaP1History2026` (primary) + `cmaP1Dashboard` (derived subset)
- **Learner state:** `cmaMayLearnerState` (canonical)
- **Telemetry:** `cmaMayPilotTelemetry` (current) + `cmaMayPilotTelemetryArchive` (historical)

The history/dashboard overlap is intentional — dashboard is a derived view of history for performance reasons, not a duplicate source of truth.

### 2.3 Hidden Dependencies

- `SessionPersistence.restore()` reads from `SAVE_KEY` and falls back to `CHECKPOINT_KEY`
- `may-core.js` reads `cmaMaySelectedLearnerId` across 3 independent code paths
- `may-coaching-orchestrator.js` writes telemetry to 3 related keys (current, snapshot, archive)
- `may-core.js` debug panel reads 4 logs (usage, safety, gate, telemetry)
